# Genesis Rhod 600 lighting integration — hardware and service validation

**LAURIDELL, 11 November 2026.** The user's keyboard is a Genesis Rhod 600, USB VID 1A2C / PID 8000, HID MI_01 / COL07, UsagePage FF01, Usage 0001, 8-byte HID Feature and Output reports.

## Verified
- [x] The keyboard owner captured **six-area RGB reports** from the manufacturer software. Area index layout: `07 FF 70 [A1|A2] [A3|A4] [A5|A6] 03 00`. Allowed indices 0–7; 0 off, 1 red, 2 green, 3 blue, 4 yellow, 5 cyan, 6 purple, 7 white.
- [x] The new adapter read-only detection found **exactly one** matching USB interface and verified UsagePage FF01 / Usage 0001 and both 8-byte output/feature lengths.
- [x] Vendor `ShinetekTools.exe` was **not running** at the time of HID testing, and the new adapter checks for this process before every lighting write.
- [x] Windows `HidD_SetFeature` accepted two **original owner-captured** color reports: `07 FF 70 73 11 11 03 00` (AREA1 white) and `07 FF 70 53 11 11 03 00` (AREA1 cyan). The latter restores the **last captured reference arrangement**, but the current vendor-profile colors could not be read back; claiming an exact pre-test restore would be inaccurate.
- [x] The six-zone RGB service ran for 25 seconds and processed `ERROR` (pending 1), `SUCCESS` (pending 2), then `ACK` (pending 0). No HID write error was logged. Saved event state returned to empty.
- [x] The optional per-user Windows logon task `True Mouse Art - Genesis Rhod 600` was installed and launched. Its local UDP listener accepts `RHOD600:ALERT/ERROR/SUCCESS/NOTICE/ACK` on `127.0.0.1:45894`.
- [x] The existing ntfy/Windows Event Log bridge was updated to forward minimal event codes **to both endpoints**, P93 port 45893 and Rhod 600 port 45894; simulated sockets verified the correct datagrams including `ACK`.
- [x] GitHub Actions Windows CI [run 42995083055](https://github.com/liikane/openrgb-bloody-p93/actions/runs/42995083055) passed Python notification bridge tests, five Rhod600 protocol/queue tests, P93 C++ tests, and Windows OpenRGB 1.1 plugin DLL build.
- [x] An independent Rhod600 `ALERT` event was received while background service was running; `ACK` cleared the keyboard-only queue. The mouse's preexisting pending categories `ERROR, ALERT` were **preserved** and not cleared for testing.

## Not yet verified

- [ ] Windows sign-out/sign-in automatic startup behavior in a fresh desktop session.
- [ ] Coexistence when the manufacturer app opens while the adapter is running (the driver is designed to refuse writes if ShinetekTools is detected).

## Safety boundaries
Only the **color** report family `07 FF 70 ... 03 00` can be generated by the adapter. No macro, shortcut, profile, keyboard input, firmware or unknown command is sent. If stopping the daemon, the last displayed hardware color may remain until the user's preferred vendor program takes control.

To stop keyboard animation without changing mouse alert state:

```powershell
& "C:\Users\lauri\Portable\OpenRGB-Bloody-P93-Plugin\integrations\rhod600\Manage-RhodTask.ps1" -Mode Stop
```

To remove its login task completely, use `-Mode Uninstall`.

The original P93 plugin remains independently functional. The `Ctrl+Shift+F12` hotkey is intentionally a **shared acknowledgement** (would clear both devices), so it was **not** invoked while existing mouse notifications were pending.
